## 1. 제품 정의

SlideForge는 **정보·요청·레퍼런스만 주면 전체 포트폴리오를 자동으로 만들고, 결과에서 필요한 부분만 고쳐 PDF로 내보내는 로컬 우선 도구**입니다. 사용자는 목차를 먼저 설계하거나 필드를 나눠 입력하지 않습니다. 도구가 구성과 슬라이드를 먼저 만들고, 사용자는 결과를 보고 고칠 페이지만 선택합니다.

현재 MVP의 공식 이름은 **Portfolio Builder Workspace**, 새 주 흐름은 **Auto Studio**입니다. 기존 목차 화면과 캔버스 편집기는 자동 생성 결과를 깊게 다듬는 고급 경로로 남습니다. Archive Workspace, RAG, Notion 연동, 채용 플랫폼 API는 미래 설계 문서에만 존재하며 제품 범위에 포함되지 않습니다.

### 제품이 해결하는 핵심 문제

| 문제 | SlideForge의 접근 |
| --- | --- |
| 자료는 많은데 무엇을 쓸지 정리가 안 됨 | 한 번의 입력 → 구성·슬라이드·디자인까지 자동 생성 |
| 목차/스토리 필드를 따로 채워야 함 | 긴 문장에서 제목·목적·독자·톤·페이지 수를 읽고, 나머지는 문맥으로 계획 |
| 참고 디자인을 설명하기 어려움 | 레퍼런스 파일/링크를 분석해 섹션 제목·레이아웃·팔레트 단서를 구성에 반영 |
| AI가 근거 없는 성과를 지어냄 | 자료가 없는 페이지는 빈 셀로 유지, 원문과 AI 요약 분리 보존 |
| 생성 결과를 고치려면 다시 생성해야 함 | 결과에서 해당 페이지만 선택해 문구·레이아웃 수정, 나머지는 그대로 유지 |
| 디자인을 바꾸면 이전 결과가 사라짐 | 변경 전 프로젝트 스냅샷 저장, 버전 목록에서 복원 |
| 키가 없으면 제품을 못 씀 | 로컬 결정론 엔진을 기본 경로로 두고 원격 모델은 선택 사항 |
| PDF/PPTX에서 텍스트가 깨지거나 편집이 불가 | PDF 우선, 인쇄 전용 HTML 파이프라인, 이후 이미지 기반 PPTX |

## 2. MVP 페르소나와 Job-to-be-done

| 페르소나 | 상황 | 그리고자 하는 일 (Job) | SlideForge의 대응 |
| --- | --- | --- | --- |
| 취업·이직 준비자 | 공고와 경력 자료는 있는데 포트폴리오 구조를 못 잡음 | “내 경험을 공고 요구사항에 맞는 12페이지 이야기로 정리하고 싶다” | 프롬프트 + 자료로 목차/슬라이드 초안 생성, 공고 키워드 매핑 표시 |
| 채용 담당자·검토자 | 지원자의 긴 자료보다 압축된 근거를 보고 싶음 | “핵심 역량과 실제 근거를 한 장 단위로 빠르게 확인하고 싶다” | 16:9 슬라이드, 한 페이지 한 메시지, PDF에서 선택 가능한 텍스트 |
| 콘텐츠 편집자·디자이너 | AI 초안은 좋지만 문구/배치를 직접 조정하고 싶음 | “텍스트는 한 곳만 고치고, 위치는 따로 조절하고, 스타일은 여러 번 바꿔 보고 싶다” | `content` / `visualOverrides` / `designSystem` 분리, 27종 프리셋, 자연어 디자인 요청, 버전 복원 |
| 개발·제품 검토자 | 키 없이도 흐름을 확인하고 샘플과 실데이터를 구분하고 싶음 | “실제 공고가 아닌 예시로 화면과 생성 흐름을 검증하고 싶다” | 개발용 시드 프로젝트, “실제 공고 아님” 문구, 로컬 폴백 안내, 설정/사용량 화면 |

> 주의: 현재 코드에는 개발용 샘플을 구분하는 구조화된 `isSample` 플래그나 전용 배지가 없습니다. 샘플 여부는 시드 데이터의 제목·본문·각주 문구로만 표현됩니다. 이 차이는 `docs/STATUS.md`에 기록했습니다.

## 3. MVP 범위

### 포함 (구현 대상)

- Auto Studio 입력 화면(`/`): 자료와 요청을 담는 하나의 큰 입력창, 파일/링크/붙여넣기, 참고 자료 지정, 접힌 상태의 스타일·페이지 수·모델
- 원클릭 생성 API(`POST /api/studio/create`): 자료 분류 → 레퍼런스 분석 → 구성 계획 → 전체 슬라이드 작성 → 초기 스냅샷까지 한 요청으로 처리
- 결과 검토 화면(`/studio/[id]`): 전체 페이지 미리보기, 선택한 페이지만 수정, 해당 페이지 재생성, 실행 취소/다시 실행, 디자인 변경, 버전 복원, PDF/PPTX 내보내기
- 자료 입력: 자유 텍스트, 파일 업로드, URL 가져오기, 자료 유형 9종 (파일 이름으로 자동 분류)
- 레퍼런스 분석(`POST /api/references/analyze`, `src/lib/ai/reference-analysis.ts`): 섹션 제목, 페이지 단서, 레이아웃/톤/스타일 단서 추출
- 고급 경로 — 목차/계획 화면(`/projects/[id]/outline`): 스토리, 파트, 페이지 목차, AI 재추천, 디자인 변경
- 편집기(`/projects/[id]/editor`): 슬라이드 셀 편집, 요소 배치 오버라이드, 레이아웃 변경, 생성/수정/재생성, 버전, 삭제
- 인쇄/내보내기: `/print/[id]`, PDF, 이미지 기반 PPTX
- 프로젝트 목록(`/projects`): 검색, 복제, 복원, 삭제
- 설정(`/settings`): provider/model, API 키, 사용량, 보안 안내
- 버전 스냅샷과 소프트 삭제/복원

### 제외 (설계만 존재)

- Archive Workspace 전체 UI, `ArchiveItem` / `Evidence` / `Embedding` 등 미래 엔티티
- RAG, vector DB, `sqlite-vec`, 하이브리드 검색, SourceLink 자동 인용
- Notion sync, 채용 플랫폼 API 연동
- 편집 가능한(네이티브 도형/텍스트 기반) PPTX
- 로그인/멀티유저/권한 모델, 사용량 과금

근거: `docs/ARCHIVE_FUTURE.md`, `docs/IMPLEMENTATION_PLAN.md` §4, `docs/RESEARCH.md` §1·§4.

## 4. 핵심 설계 원칙

### 4.1 로컬 우선, 원격은 선택

- 기본 생성 경로는 API 키가 필요 없는 결정론 로컬 엔진입니다(`src/lib/ai/local-outline.ts`, `src/lib/ai/local-slide.ts`).
- provider/model은 생성 화면(`ModelPicker`)과 편집기 헤더에서 선택할 수 있고, 설정 화면에서 키·Base URL을 저장합니다.
- 선택한 원격 제공자에 키가 없거나 호출이 실패하면 로컬 결과로 폴백하고 사용자에게 알림을 표시합니다(`src/lib/ai/index.ts`의 `resolveConfig()`와 `notice`).
- 현재 환경에는 AI API 키가 없으므로 **원격 호출 성공 경로는 코드만 존재하고 실제 검증은 되지 않았습니다.**

### 4.2 텍스트는 한 곳, 움직임은 별도 오버라이드

- 의미 단위 텍스트의 유일한 진실 소스는 `slide.content`입니다.
- 캔버스에서 텍스트를 클릭해 수정하면 `content`만 갱신됩니다. 위치·크기·순서·숨김은 `elementId`를 키로 하는 `slide.visualOverrides`에 저장됩니다.
- 의미 단위 레이아웃은 `slide.layout.kind`로 선택합니다. HTML은 `content + layout + visualOverrides + designSystem`을 합친 **파생 결과**이며 직접 편집 대상이 아닙니다.
- `visualOverrides`의 현재 필드는 `x`, `y`, `width`, `height`, `z`, `hidden`입니다. 캔버스에서는 `Alt + 드래그`로 이동하고, 노드 패널의 숫자 입력으로 크기/순서를 조정합니다.

### 4.3 디자인은 모든 단계에서 다룬다

디자인 프리셋과 자연어 디자인 방향은 다음 진입점에서 동일한 설계 상태를 읽고 써야 합니다.

| 단계 | 현재 구현 |
| --- | --- |
| 생성 composer (`/`) | `StylePicker`, `ModelPicker` 구현됨 |
| 목차/계획 (`/projects/[id]/outline`) | `StylePicker`, 자연어 디자인 요청, `POST /api/projects/[id]/design` 구현됨 |
| 편집기 (`/projects/[id]/editor`) | 헤더 스타일 선택, 디자인 탭, 자연어 요청 구현됨 |
| 완료 후 설정 (`/settings`) | **미구현** — 현재 설정 화면은 모델/키/사용량/보안 안내만 제공 |

기본 프리셋은 `modern-editorial`입니다. `src/lib/design.ts`에는 큐레이션 7종과 확장 20종, 총 27종이 등록되어 있고 모두 선택 가능합니다. 다만 확장 20종의 세부 디자인 품질은 순차적으로 다듬어지는 상태이며 `StylePicker` 화면에도 그렇게 안내합니다.

### 4.4 변경 전 스냅샷

다음 동작은 상태를 바꾸기 전에 `versions(kind='project'|'slide')` 불변 스냅샷을 먼저 남깁니다.

- 목차 저장 / 목차·디자인 변경 (`/api/projects/[id]/outline`)
- 디자인 변경 (`/api/projects/[id]/design`)
- 전체 재생성 (`/api/projects/[id]/regenerate`)
- 페이지 순서 변경 (`/api/projects/[id]/slides/reorder`)
- 슬라이드 수정·생성·부분 수정·삭제 (`/api/projects/[id]/slides/**`)
- 프로젝트 수정·삭제 (`/api/projects/[id]`)
- 수동 스냅샷 (`/api/projects/[id]/versions`)

스냅샷 목록은 편집기 왼쪽 “버전” 탭에서 확인하고 복원할 수 있습니다. 복원 자체도 “복원 이전 상태”를 다시 스냅샷으로 남깁니다(`src/lib/repo.ts`).

### 4.5 빈 셀 보존과 근거 없는 문장 금지

- 자료가 없는 페이지는 내용을 지어내지 않고 빈 셀/안내 문구로 남깁니다.
- 개발용 시드도 6페이지(AI 영상 제작 도전과 실패)와 10페이지(실제 구현·개발 현황)를 `rawInput: "내용 입력 필요"`, `footnote: "내용 입력 필요"`로 비워 둡니다.
- 편집기 “페이지 원문·메모”에도 “자료가 없는 문장은 빈 셀로 남습니다”라고 안내합니다.

### 4.6 샘플은 샘플로

- `npm run seed`는 “공카 AI 마케터 맞춤 포트폴리오” 개발용 예시 프로젝트를 만들거나 재사용합니다.
- 시드 자료 제목은 `[개발용 예시] ...`이고 본문에는 “실제 공카의 채용 공고가 아닙니다”, 각주에는 “개발용 예시”가 반복됩니다.
- 실제 공고는 사용자가 이후 직접 입력합니다. 샘플을 실제 지원 이력이나 회사 성과로 소개하지 않습니다.
- 위 원칙은 문서와 시드 문구로는 지켜지지만, 구조화된 플래그/UI 배지는 아직 없습니다.

### 4.7 PDF 우선, 이미지 PPTX는 그다음

- 1순위 출력은 PDF입니다. 슬라이드 한 장이 PDF 한 페이지가 되고 텍스트 선택이 가능합니다.
- PPTX는 검증된 인쇄 결과를 슬라이드별 PNG로 캡처해 `PptxGenJS`의 `LAYOUT_WIDE`에 넣는 **이미지 기반** 방식입니다. 원본 프로젝트는 계속 셀 단위로 편집할 수 있지만, 생성된 PPTX의 텍스트/도형은 편집할 수 없습니다.
- 편집형 PPTX는 이후 별도 단계입니다.

### 4.8 삭제 안전장치

- 프로젝트/페이지 삭제는 `DeleteDialog`를 거칩니다.
- 다이얼로그는 삭제 대상 제목, 영향 범위, 스냅샷 보존 사실을 보여줍니다.
- 정확히 `삭제`를 입력하고 동의 체크박스를 켜야 “최종 삭제”가 활성화됩니다.
- 실제 DB 삭제가 아니라 `deletedAt`을 기록하는 소프트 삭제이며, 프로젝트 목록의 “삭제된 항목”과 복원 API로 되돌릴 수 있습니다.

### 4.9 보안과 신뢰 경계

- API 키는 서버 SQLite `secrets` 테이블에 저장하고, UI 응답은 `첫 6자···마지막 4자`로 마스킹합니다. UI에서 저장한 키는 환경변수보다 우선합니다.
- 자료 원문(공고·문서·URL)은 명령이 아니라 **데이터**로만 취급합니다. React 렌더링으로 이스케이프하고, `dangerouslySetInnerHTML` / `eval` / `new Function`을 사용하지 않습니다.
- API 경계 입력은 Zod로 검증합니다.
- 업로드는 20MB 제한, 허용 확장자/MIME 검사, 무작위 저장 파일명을 사용합니다.
- URL 가져오기는 300KB 응답 제한, 12초 타임아웃, 리다이렉트 최대 3회, DNS/사설 IP 차단으로 SSRF를 완화합니다.
- 다중 사용자 인증, 속도 제한, 감사 로그는 현재 범위 밖입니다.

### 4.10 입력은 한 번, 생성은 자동, 수정은 선택

기본 흐름의 사용자 조작은 세 가지입니다. **정보와 요청 붙여넣기 → 파일/링크 넣기 → 생성 버튼**. 목적·독자·톤·페이지 수는 별도 필드 없이도 긴 문장에서 읽습니다(`src/lib/intake.ts`). 파일은 이름과 MIME으로 자료 종류를 자동 분류하고, ‘참고로 분석’을 켠 파일은 구성/스타일 레퍼런스로 따로 분석됩니다.

`POST /api/studio/create`는 다음을 한 번에 수행합니다.

1. 업로드/URL/붙여넣기 자료 읽기와 종류 분류
2. 참고 자료의 섹션 제목·레이아웃·팔레트 단서 추출
3. 구성 계획(목차·스토리·시각 방향) 수립
4. 목차의 각 항목에 맞춰 슬라이드 본문과 레이아웃 작성
5. ‘처음 생성한 상태’ 스냅샷 저장 후 결과 페이지로 이동

사용자는 `/studio/[id]`에서 전체 페이지를 먼저 보고, 고치고 싶은 페이지만 눌러 문구·레이아웃을 바꾸거나 그 페이지만 다시 생성합니다. 목차 편집기와 캔버스 편집기는 이 자동 결과를 더 깊게 다듬고 싶을 때 쓰는 고급 경로이며, 기본 흐름에서 거쳐야 하는 필수 단계가 아닙니다.

## 6. 사용자 흐름

### 6.1 랜딩 → 자동 생성 (`/` → `/studio/[id]`)

1. 사용자가 **하나의 큰 입력창**에 정보와 요청을 긴 문장으로 붙여넣습니다. `제목:`, `목적:`, `독자:`, `톤:`, `12페이지` 같은 단서는 자동으로 읽습니다(`parseIntake()`). 따로 필드를 채우지 않아도 됩니다.
2. 파일, 웹 링크, 별도 붙여넣기 자료를 추가합니다. 파일 이름으로 자료 종류가 자동 분류되고, 필요하면 종류를 바꿀 수 있습니다.
3. 참고용 파일/링크는 ‘참고로 분석’에 체크하고 역할(구성/스타일/둘 다)을 정합니다. 기본값은 자동 판별입니다.
4. 스타일과 페이지 수는 접힌 설정 패널에 있습니다. 비워두면 참고 자료에서 스타일 단서를 찾고, 없으면 `modern-editorial`을 씁니다. 모델 역시 선택 사항입니다.
5. “포트폴리오 생성”이 `POST /api/studio/create`를 한 번 호출합니다. 구성 계획과 모든 슬라이드를 만든 뒤 초기 스냅샷을 남깁니다.
6. 완료되면 `/studio/[id]`로 이동합니다. 목차 확정 단계는 거치지 않습니다.

### 6.2 자료 입력

지원하는 자료 유형 9종은 다음과 같습니다.

`job-posting`(채용공고), `resume`(이력서), `career-history`(경력기술서), `cover-letter`(자기소개서), `portfolio`(기존 포트폴리오), `project-doc`(프로젝트 문서), `image`(이미지·스크린샷), `website`(참고 웹사이트), `text`(자유 텍스트).

입력 방식은 네 가지입니다.

- 정보와 요청을 담은 긴 문장 (`master-prompt`)
- 따로 보관할 자료 붙여넣기 (공고 원문 등)
- 파일 업로드 (PDF, DOCX, PPTX, TXT, MD, PNG, JPG, JPEG, GIF, WEBP / SVG, 최대 20MB)
- 공개 URL 가져오기 (`POST /api/import-url`, 참고 URL은 생성 시 서버에서 읽음)

**참고 자료 분석**은 별도 경로입니다. ‘참고로 분석’을 켠 파일/URL/텍스트는 `analyzeReference()`가 섹션 제목, 페이지 단서, 레이아웃 후보, 톤, 스타일 단서, 팔레트 힌트로 바꿉니다(`confidence: "heuristic"`, 규칙 기반). 이 결과는 구성 계획의 목차 순서와 시각 방향에 반영되고, 원문과 함께 `sources.metadata.analysis`에 보존됩니다. 이미지의 경우 브라우저에서 추출한 대표 색상도 힌트로 붙습니다.

**채용공고 원문과 AI 요약의 분리**가 핵심입니다. 원문은 `originalContent`로 그대로 보존되고, 생성에 사용되는 요약/추출 결과는 `extractedContent`에 따로 저장됩니다. 목차 화면의 “공고 요구사항 매핑”은 이 요약에서 키워드를 찾아 페이지와 연결하고, 편집기 “자료” 탭은 원문/요약 글자 수와 원문 미리보기(최대 6,000자)를 보여줍니다.

### 6.3 결과 검토 · 부분 수정 (`/studio/[id]`)

기본 흐름의 두 번째 화면입니다. 전체 페이지를 16:9 미리보기로 한눈에 보고, 수정이 필요한 페이지만 눌러 아래 작업을 합니다.

| 영역 | 가능한 작업 |
| --- | --- |
| 상단 | 모델 선택, 27종 디자인 프리셋 변경, 구성 보기, PDF/PPTX 내려받기, 캔버스 편집기로 이동 |
| 페이지 그리드 | 페이지별 미리보기와 제목, 선택 상태 표시 |
| 선택한 페이지 | 줄글로 내용/요청을 적어 해당 페이지 다시 만들기(기본), 필드별 직접 수정과 레이아웃 변경은 접힌 메뉴, 전체 다시 만들기 |
| 실행 취소 | `Ctrl+Z` 실행 취소, `Ctrl+Shift+Z` / `Ctrl+Y` 다시 적용 (입력 중에는 무시) |
| 이전 상태 | 페이지별/프로젝트 단위 스냅샷 목록에서 복원 |

기본 수정 방법은 **줄글 한 칸**입니다. 사용자가 적은 문장을 `PATCH /api/projects/[id]/slides/[slideId]`로 `rawInput`에 저장한 뒤 `POST /api/projects/[id]/slides/[slideId]/generate`를 호출하면, 해당 슬라이드의 제목·문단·레이아웃을 다시 만듭니다. 생성 전 슬라이드 스냅샷이 남고 `Ctrl+Z`로 되돌릴 수 있습니다. 필드별 수정과 레이아웃 선택은 “필드별로 직접 수정” 안에 접어 두어, 값이 딱 맞아떨어질 때만 꺼내 쓰게 했습니다. 구성 전체를 바꾸고 싶을 때만 고급 경로(`/projects/[id]/outline`, `/projects/[id]/editor`)로 이동합니다.

### 6.4 목차/계획 (`/projects/[id]/outline`) — 고급 경로

- 스토리 기반: 목적, 대상 독자, 핵심 메시지, 톤, 전체 줄거리, 시각 방향 편집
- 파트 추가/삭제
- 페이지 추가/복제/이동/삭제. 최소 3페이지 유지
- 각 페이지의 제목, 역할, 핵심 메시지, 레이아웃(`LayoutKind`) 편집
- “구성 다시 제안”(`POST /api/projects/[id]/replan`)
- 스타일 프리셋 선택과 자연어 디자인 요청
- “구성 확정”은 `POST /api/projects/[id]/outline`으로 저장하고 스냅샷을 남김
- “구성 확정하고 편집기로 이동”은 저장 후 `/projects/[id]/editor`로 이동

### 6.5 편집기 (`/projects/[id]/editor`) — 고급 경로

| 영역 | 가능한 작업 |
| --- | --- |
| 왼쪽: 페이지 | 페이지 선택, 상태/잠금 확인 |
| 왼쪽: 노드 | 요소 선택, `x/y/width/height/z` 숫자 편집, 숨기기/표시 |
| 왼쪽: 버전 | 수동 스냅샷 저장, 버전 목록에서 복원 |
| 왼쪽: 자료 | 원문/요약 글자 수 확인, 원문 펼쳐 보기 |
| 중앙 캔버스 | 1280×720 미리보기, 확대/축소(30~100%), 레이아웃 선택, 텍스트 직접 편집, `Alt + 드래그` 이동, 페이지 잠금/해제 |
| 오른쪽: 입력·생성 | 페이지 원문/메모, 이 페이지 생성, 콘텐츠 유지 후 레이아웃만 변경, 자연어 부분 수정, 전체 재생성(콘텐츠/디자인/둘 다, 잠긴 페이지 제외 옵션) |
| 오른쪽: 디자인 | 27종 프리셋 선택, 자연어 디자인 요청, 현재 디자인 토큰 확인 |
| 오른쪽: 내보내기 | PDF 생성, PPTX 생성, 인쇄 미리보기, 프로젝트 삭제 |

텍스트/배치 변경은 450ms 디바운스로 자동 저장됩니다. 생성·재생성·버전 복원 후에는 편집기 실행 취소 기록이 초기화됩니다.

**실행 취소/다시 실행 키**

- 실행 취소: `Ctrl+Z` / `Cmd+Z`
- 다시 실행: `Ctrl+Shift+Z` / `Cmd+Shift+Z` / `Ctrl+Y`
- 입력 중(`input`, `textarea`, `select`, `contenteditable`)에는 단축키가 동작하지 않습니다.
- 현재 히스토리는 편집기 컴포넌트의 로컬 상태이며 최근 60개 작업만 유지됩니다. 페이지 순서 변경은 히스토리에 포함되지 않고, `zundo`/Zustand 미들웨어를 사용하지 않습니다.

### 6.6 인쇄·내보내기

- 인쇄 미리보기: `/print/[id]?clean=1`. 편집 UI를 제외한 슬라이드만 표시합니다.
- PDF: `GET /api/projects/[id]/export?format=pdf`. Playwright Chromium으로 인쇄용 HTML을 렌더링합니다.
- PPTX: `GET /api/projects/[id]/export?format=pptx`. 슬라이드별 PNG를 캡처해 이미지 슬라이드로 삽입합니다.
- 생성된 파일은 `/api/exports/[filename]`으로 내려받습니다.

### 6.6 프로젝트 목록·설정

- `/projects`: 제목 검색, 삭제된 항목 포함 보기, 프로젝트 열기/복제/복원/삭제
- `/settings`: 제공자·모델·Base URL, API 키 저장/삭제, 키 연결 상태(마스킹), 호출/토큰/예상 비용과 최근 호출 기록, 보안 원칙 안내

## 7. 12페이지 샘플 포트폴리오 정책

개발용 시드(`scripts/seed.ts`)는 아래 제목을 **정확한 순서와 문구로** 사용합니다.

1. 표지·자기소개
2. 핵심 역량
3. 마케팅 실무 경험
4. 실무 생성형 AI 활용 경험
5. 마케팅 업무에서 발견한 문제
6. AI 영상 제작 도전과 실패
7. AI·개발 학습 과정
8. AI 서비스 구현 경험
9. 마케팅 AX 워크플로우 기획
10. 실제 구현·개발 현황
11. 향후 자동화 확장 계획
12. 공카에서의 기여 방향

정책:

- 시드는 `modern-editorial` 기본 디자인과 위 12개 목차를 사용합니다.
- 6페이지와 10페이지는 의도적으로 비워 두며 “내용 입력 필요” 상태로 표시합니다. 확인되지 않은 수치/성과를 만들지 않습니다.
- 모든 예시 각주와 자료 원문은 실제 공고·실적이 아님을 명시합니다.
- 이미 동일한 제목의 12페이지 샘플이 있으면 새로 만들지 않고 재사용합니다.
- 실제 지원 공고는 사용자가 직접 입력하며, 샘플 문구를 실지원 이력처럼 서술하지 않습니다.

## 9. 보안 요구사항

1. **키 보관**: UI에서 입력한 키는 서버 SQLite `secrets`에만 저장하고 응답에서는 마스킹합니다. 환경변수는 DB에 값이 없을 때 사용됩니다.
2. **폴백 투명성**: 키가 없거나 호출이 실패하면 로컬 생성으로 전환하고 화면에 이유를 표시합니다.
3. **입력 검증**: 프롬프트/슬라이드/오버라이드/요청 본문은 Zod 스키마로 검증합니다.
4. **업로드 검사**: 확장자와 MIME을 함께 확인하고, 저장 파일명은 무작위 ID + 검증된 확장자만 사용합니다. 추출 텍스트는 12,000자로 제한합니다.
5. **URL 안전성**: 사설/예약 주소와 localhost를 차단하고 DNS를 확인하며, 응답 300KB·12초·리다이렉트 3회로 제한합니다.
6. **콘텐츠 실행 금지**: 자료와 AI 결과는 텍스트로만 취급하고 임의 JavaScript/HTML 주입을 실행하지 않습니다.
7. **삭제 안전**: 정확한 확인 문구와 동의 체크, 소프트 삭제, 복원 경로를 제공합니다.
8. **범위 밖**: 인증/권한/다중 테넌시, 속도 제한, 외부 감사 시스템은 MVP에 포함되지 않습니다.

## 10. 용어 정리

| 용어 | 의미 |
| --- | --- |
| Portfolio Builder Workspace | 현재 구현된 생성·목차·편집·내보내기 제품 영역 |
| Archive Workspace | 미래 자료 수집/검색/인용 영역. 현재는 `docs/ARCHIVE_FUTURE.md`에만 존재 |
| semantic layout | 슬라이드의 의미 단위 배치 종류(`LayoutKind`). 예: `statement`, `timeline`, `grid` |
| visualOverrides | `elementId`별 위치/크기/순서/숨김 값. 텍스트를 복사하지 않음 |
| 스냅샷 | 변경 전 상태를 담은 불변 `versions` 레코드 |
| 소프트 삭제 | `deletedAt`만 기록하고 데이터를 남기는 삭제 방식 |
| 로컬 우선 | AI API 키 없이도 결정론 엔진으로 전체 흐름을 사용할 수 있는 원칙 |
