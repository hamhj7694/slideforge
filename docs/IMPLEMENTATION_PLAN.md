# Phase 1 구현 계획 — Portfolio Builder Workspace

> 문서 작성 단계에서는 빌드/테스트를 실행하지 않았습니다. 아래 항목은 구현 에이전트가 수행할 작업과 인수 기준입니다.

## 1. 최종 완료 조건 (2026-11-26)

공카 AI 마케터 지원용 **12페이지 포트폴리오 PDF**를 생성/다운로드할 수 있어야 한다.

기본 디자인은 **Modern Editorial**이고, 목차는 아래 순서/문구를 정확히 따른다. 자료가 없는 페이지는 **빈 셀로 남기며 내용을 지어내지 않는다.**

디자인 프리셋과 자연어 디자인 방향은 **생성 composer · 목차/계획 화면 · 에디터 · 완료 후 Settings**에서 선택/변경할 수 있어야 한다. 모든 디자인 변경, 전체 재생성, "새로 만들기", "새 버전" 액션은 변경을 적용하기 전에 `versions(kind='project')` 불변 스냅샷을 먼저 저장한다. 기존 결과는 절대 덮어쓰지 않으며 버전 목록에서 전환/복원할 수 있다. 메인 생성의 "새로 만들기"는 다른 스타일의 **별도 새 프로젝트**를 만들고, 에디터의 "새 버전"은 현재 프로젝트의 **버전드 디자인 변형**을 만든다.

1. 표지·자기소개
2. 핵심 역량
3. 마케팅 실무 경험
4. 실무 생성형 AI 활용 경험
5. 마케팅 업무에서 발견한 문제
6. AI 영상 제작 도전과 실패
7. AI·개발 학습 과정
8. AI 서비스 구현 경험
9. 마케팅 AX 워크플로우 기획
10. 실제 구현·개발 현황
11. 향후 자동화 확장 계획
12. 공카에서의 기여 방향

개발 중에는 **샘플/예시 공고**만 사용하며, 화면과 문서 어디에서도 이를 실제 공고로 소개하지 않는다. 실제 공고는 사용자가 이후 입력한다.

## 2. 작업 체크리스트

### A. 데이터/계약

- [ ] SQLite + Drizzle 스키마 확정: `document`, `rawInput`, `slide`, `slideContent`, `layoutOverride`, `versions(kind='project')`, `apiKeySetting`, `exportArtifact`
  - 인수: content/override/version이 분리 저장되고, `elementId`로 연결된다. `versions`는 불변이며 design 프리셋 + 자연어 디자인 방향을 포함한 스냅샷을 저장한다.
- [ ] Zod 스키마와 TypeScript 타입 정렬 (`src/lib/schemas.ts`, `src/lib/types.ts`)
  - 인수: 잘못된 슬라이드/오버라이드 입력이 API 경계에서 거부된다.
- [ ] 기본 디자인 프리셋 **Modern Editorial** 등록 (`src/lib/design.ts`)
  - 인수: 새 문서를 만들면 별도 선택 없이 Modern Editorial이 적용된다.

### B. 생성/AI

- [ ] 로컬 결정적 outline/slide 생성 경로 연결 (`src/lib/ai/local-outline.ts`, `local-slide.ts`)
  - 인수: AI 키가 없는 환경에서도 위 12개 목차와 슬라이드 뼈대가 생성된다.
- [ ] 프롬프트 입력창 근처 + 에디터 헤더에 provider/model dropdown 배치
  - 인수: 두 곳의 선택값이 동일한 생성 설정으로 반영된다.
- [ ] Settings 화면에서 API 키 server-side SQLite 저장/교체/삭제
  - 인수: GET 응답은 마스킹값만 포함하고, 키 값은 클라이언트/로그/버전에 노출되지 않는다.
- [ ] 폴백 체인 구현: 선택 모델 + 키 → 원격 / 키 없음·실패 → 로컬
  - 인수: 폴백 시 화면에 "선택한 모델의 API 키가 없어 로컬 생성으로 전환했습니다." 안내가 보인다.
- [ ] 빈 셀 정책 적용
  - 인수: 자료가 없는 페이지는 빈 상태로 저장/렌더링되고 자동 완성 문장이 없다.

### B-2. 디자인 선택/변경과 버전 안전

- [ ] 디자인 프리셋 + 자연어 디자인 방향 선택/변경 UI: 생성 composer, 목차/계획 화면, 에디터, 완료 후 Settings
  - 인수: 네 진입점 모두 동일한 design 상태를 읽고 쓰며, 기본값은 Modern Editorial이다.
- [ ] 변경 전 `versions(kind='project')` 불변 스냅샷 자동 저장
  - 인수: 디자인 변경·전체 재생성·새로 만들기·새 버전 실행 직전에 스냅샷이 먼저 기록되고, 스냅샷 실패 시 변경이 적용되지 않는다.
- [ ] 버전 목록/전환/복원 UI
  - 인수: 이전 결과를 덮어쓰지 않고 목록에서 선택해 전환/복원할 수 있다.
- [ ] "새로 만들기"와 "새 버전" 동작 분리
  - 인수: 메인 생성의 새로 만들기는 다른 스타일의 별도 프로젝트를 만들고, 에디터의 새 버전은 현재 프로젝트의 버전드 디자인 변형을 만든다.

### C. 캔버스 편집

- [ ] 의미 단위 텍스트 편집: `slide.content`만 변경
  - 인수: 텍스트를 수정하면 프리뷰/PDF/버전에 동일하게 반영되고 별도 텍스트 사본이 생기지 않는다.
- [ ] 이동/리사이즈를 `elementId` 키 `layoutOverride`로 저장
  - 인수: 위치를 바꿔도 `slide.content`는 변경되지 않는다.
- [ ] Zustand undo/redo: 텍스트 편집 + 페이지 리오더
  - 인수: `Ctrl/Cmd+Z`, 재실행으로 두 종류의 변경이 모두 복구된다.
- [ ] 페이지 리오더 UI (드래그) 및 순서 영속화
  - 인수: 새로고침 후에도 순서가 유지되고 undo 대상이다.

### D. 샘플/콘텐츠

- [ ] 개발용 샘플 공고 시드 + `isSample: true` + UI "샘플 공고" 배지
  - 인수: 실제 공고로 오인될 문구가 없고, 실제 공고 입력 경로가 별도로 존재한다.
- [ ] 12페이지 목차 시드(위 문구 그대로)
  - 인수: 페이지 수와 제목/순서가 완료 조건과 정확히 일치한다.
- [ ] 누락 콘텐츠 페이지 empty-cell 렌더링
  - 인수: 빈 페이지가 "내용 없음"으로 채워지지 않고 빈 셀로 표시된다.

### E. 내보내기

- [ ] print-safe HTML 렌더러 (content + design + overrides)
  - 인수: 편집 화면과 PDF의 레이아웃/순서가 일치한다.
- [ ] Playwright(설치된 Chrome) 기반 PDF 생성 `/api/export/pdf`
  - 인수: 12페이지 PDF가 다운로드되고 빈 셀이 유지된다.
- [ ] PDF 검증 후에만 이미지 기반 PPTX 착수 (`PptxGenJS`)
  - 인수: PDF가 동작하기 전에는 PPTX API/UI를 활성화하지 않는다.

### F. 삭제 안전장치

- [ ] 삭제 모달: `삭제` 정확 입력 + 동의 체크박스
  - 인수: 두 조건 중 하나라도 충족되지 않으면 삭제 버튼이 활성화되지 않는다.
- [ ] soft delete + restore
  - 인수: 삭제 후 목록에서 숨겨지지만 DB에 남고, 복구 시 content/layout/version이 그대로 돌아온다.

## 3. 완료 판정 체크리스트

- [ ] 환경 변수에 AI 키가 없어도 로컬 생성으로 12페이지 초안이 만들어진다.
- [ ] provider/model을 선택했지만 키가 없으면 로컬 폴백 + 안내가 표시된다.
- [ ] Settings에서 키를 저장/교체/삭제할 수 있고 UI에는 마스킹값만 보인다.
- [ ] 텍스트 편집이 `slide.content` 단일 소스에만 반영된다.
- [ ] 이동/리사이즈가 `elementId` 기반 오버라이드로만 저장된다.
- [ ] 텍스트 편집과 페이지 리오더가 모두 undo/redo 된다.
- [ ] 12개 제목이 지정된 순서/문구와 정확히 같다.
- [ ] 자료가 없는 페이지는 빈 셀이며 지어낸 내용이 없다.
- [ ] 샘플 공고가 화면에 명확히 표시되고 실공고로 소개되지 않는다.
- [ ] 기본 디자인이 Modern Editorial이다.
- [ ] 디자인 프리셋/자연어 방향이 생성 composer, 목차 계획, 에디터, 완료 후 Settings에서 모두 선택/변경된다.
- [ ] 디자인 변경·전체 재생성·새로 만들기·새 버전 전에 `versions(kind='project')` 스냅샷이 먼저 저장되고 기존 결과가 덮어써지지 않는다.
- [ ] 버전 목록에서 이전 결과로 전환/복원할 수 있다.
- [ ] 새로 만들기는 별도 프로젝트, 에디터 새 버전은 현재 프로젝트의 디자인 변형으로 동작한다.
- [ ] Playwright Chrome으로 12페이지 PDF를 다운로드할 수 있다.
- [ ] `삭제` 입력 + 동의 + soft delete + restore 흐름이 동작한다.
- [ ] PPTX는 PDF 검증 이후 단계로 남겨 둔다.
